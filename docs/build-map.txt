0. 분류 기준
------------
기획안 3장의 시스템 구조를 그대로 쪼갰다. 9개 덩어리다.
아래에서 "코드"와 "검증"을 분리해서 적는다. 이유는 19장 때문이다 —
MVP 성공 기준이 전부 "사람이 봤을 때 맞는가"이고, 그건 코드가 있다고
통과되는 게 아니다.

  코드   = 그 조항의 동작이 코드로 존재하고 테스트가 돈다
  검증   = 실제 방송 원본 / 실제 완성본 / 실제 API 키로 돌려서 확인했다


1. 학습기 (Learning)  — 기획안 4장, 12장
=========================================
이 시스템의 핵심. 12.3이 "B가 없으면 규칙 엔진에 머문다"고 못박은 곳.

  A. YouTube Content Learning (4장)
     코드  aicut/intelligence/reference.py
           aicut/intelligence/youtube.py     검색 + 공개 지표 수집 (4.2)
           aicut/intelligence/knowledge.py   4.5 제작 지식으로 통합
           aicut/intelligence/quota.py       11.4 PT 자정 쿼터
     동작  watch()가 영상 파일을 디코딩해 프레임을 뽑고, analyze()가
           그 프레임을 AI에게 보여준다. 답만 저장하고 프레임은 삭제(4.6).
     CLI   aicut learn reference --file ID=PATH
     검증  ✗  실제 YouTube API 키로 돌린 적 없음

  B. Source-to-Output Learning (12.3 B)  ← 핵심 차별점
     코드  aicut/intelligence/source_output.py
     동작  원본↔완성본 대사 정렬로 선택/제거 구간을 계산하고,
           두 영상의 프레임을 원본 먼저·완성본 나중 순으로 AI에게 보여준다.
           선택/제거/재배치/반복/강조 판정은 AI가 한다.
     CLI   aicut learn pairs --source-file --output-file
                             --source-transcript --output-transcript
     검증  ✗  실제 원본↔완성본 쌍으로 돌린 적 없음

  C. Performance Learning (12.2)
     코드  aicut/pipeline/performance.py   자기 채널 한정 (4.2 사실관계 주의)
     검증  ✗

  출처  merge_intervals / complement 는 코덱스 구현
        (legacy/backend/learning.py:27,38,54)에서 가져왔다.

현재 상태 요약
==============
코드로 존재하는 비율 :  기획안 23개 장 중 조항 단위로 대부분 코드가 있다.
검증된 비율         :  9번 인프라만. 1~8번은 실제 영상으로 돌린 적이 없다.

19장이 정한 관문 기준으로 보면:
  MVP 1 (레퍼런스 분석)   코드 있음 / 성공 기준 미측정
  MVP 2 (방송 이해)       코드 있음 / 성공 기준 미측정
  MVP 3 (콘텐츠 발견)     코드 있음 / 성공 기준 미측정  ← "이 프로젝트의 첫 관문"
  MVP 4 (원본↔완성본)     코드 있음 / 성공 기준 미측정
  MVP 5~9                 코드 있음 / 성공 기준 미측정

즉 "몇 퍼센트"를 코드 기준으로 말하면 높게 나오고, 19장 관문 기준으로
말하면 0개 통과다. 이 둘을 섞어서 하나의 숫자로 말하지 않는다.
