# AI 자율형 생방송 콘텐츠 제작 시스템 기획안 (원본)

Broadcast-to-YouTube Autonomous Content Producer

> 이 파일은 `통합 기획안 v1`이 "상위 기획 골격: ai편집.txt"로 참조하는 원본 문서다.
> 사용자가 제공한 원문이며 임의로 요약·수정하지 않는다.
>
> **v1과 충돌하는 지점에서는 `docs/spec-v1.ko.md`(통합 기획안 v1)가 우선한다.**
> v1은 이 문서의 골격을 유지하되 고정 임계값 제거(17장), 데이터 모델 교체(13장),
> FFmpeg 기술 오류 수정(10.4), 사람 검수 게이트 승격(11.3),
> 3종 학습 루프 복원(12.3)을 적용한 판이다.

---

## 1. 프로젝트 개요

### 1.1 프로젝트명

AI 자율형 생방송 콘텐츠 제작 시스템
Broadcast-to-YouTube Autonomous Content Producer

### 1.2 프로젝트 한 줄 정의

긴 생방송 영상 하나를 AI가 전체적으로 이해하고, 현재 YouTube에서 실제로 제작되고
있는 영상들의 구성, 편집, 스토리텔링, 장면 선택, 제목, 썸네일 및 시청자 반응 등을
분석하여 제작 지식을 확보한 뒤,

생방송 안에서 독립적으로 콘텐츠가 될 수 있는 내용을 스스로 발견하고, 콘텐츠의
개수와 종류, 필요한 원본 장면, 영상의 구성 방식, 편집 방법까지 스스로 결정하여
여러 개의 YouTube 영상을 제작하는 시스템이다.

### 1.3 프로젝트의 핵심

이 시스템은 단순한 "자동 하이라이트 추출 프로그램"이 아니다.

```
생방송
→ 전체 영상 이해
→ 의미 있는 콘텐츠 발견
→ 콘텐츠 가치 판단
→ YouTube 제작 패턴 참고
→ 콘텐츠별 영상 기획
→ 필요한 원본 장면 검색
→ 장면 재구성
→ 자동 편집
→ 제목/썸네일/설명 생성
→ YouTube 업로드
→ 실제 시청자 반응 분석
→ 다음 제작에 반영
```

## 2. 기존 자동 편집 시스템과의 차이

일반적인 자동 편집 시스템:

```
긴 영상 → 재미있는 장면 탐색 → 장면 추출 → 클립 생성
```

본 프로젝트:

```
긴 생방송
→ 방송 전체 이해
→ 방송에서 발생한 사건과 흐름 파악
→ 서로 연결된 장면 파악
→ 독립적인 콘텐츠 후보 발견
→ 콘텐츠별 가치 판단
→ YouTube 콘텐츠 제작 패턴 분석
→ 콘텐츠별 제작 전략 결정
→ 필요한 장면 검색
→ 원본 장면 재구성
→ 자동 편집
→ 완성된 YouTube 영상 제작
```

핵심적인 차이는 "좋은 장면을 찾는 것"이 아니라
**"방송에서 어떤 콘텐츠가 존재하는지 이해하는 것"**이다.

---

## 3. 최종 목표

사용자가 4~10시간 정도의 생방송 영상 하나를 입력하면 AI가 방송 전체를 분석한다.
AI는 방송 안에서 의미 있는 콘텐츠를 스스로 찾아낸다.

```
생방송 1개 → 장편 영상 4개 + Shorts 5개
생방송 1개 → 장편 영상 2개 + Shorts 3개
생방송 1개 → 장편 영상 1개
생방송 1개 → 제작 가치가 있는 콘텐츠 없음
```

처럼 결과가 달라질 수 있다. **영상 개수는 하드코딩하지 않는다.**

## 4. 핵심 설계 철학

### 4.1 영상 구조를 하드코딩하지 않는다

다음과 같은 구조를 시스템의 고정 규칙으로 사용하지 않는다.

```
Hook → Context → Conflict → Climax → Resolution
```

위 구조는 하나의 콘텐츠에서는 적합할 수 있지만 모든 YouTube 영상에 적합한
구조는 아니다. 따라서 AI가 콘텐츠의 특성을 분석하고 각 콘텐츠에 맞는 구조를
스스로 결정해야 한다.

### 4.2 콘텐츠 개수를 하드코딩하지 않는다

"생방송 하나에서 무조건 3개를 만든다." / "무조건 5개를 만든다." 같은 규칙을
사용하지 않는다. AI가 방송의 실제 내용을 분석한 뒤 제작할 콘텐츠의 개수를 결정한다.

### 4.3 콘텐츠 종류를 하드코딩하지 않는다

게임, 토크, 합방, 사건 등의 분류를 최종 출력의 고정된 카테고리로 사용하지 않는다.
AI가 방송 전체를 이해하면서 어떤 의미 있는 흐름과 사건이 존재하는지를 발견한다.

### 4.4 시간순 편집을 강제하지 않는다

원본 방송의 시간 순서는 데이터일 뿐이다.
콘텐츠를 만들기 위해 필요한 경우 서로 다른 시간대의 장면을 연결할 수 있다.

```
05:12:31 → 01:42:10 → 03:21:42 → 05:13:10
```

단순히 순서를 섞는 것이 아니라 시청자가 내용을 이해할 수 있도록 맥락을 유지해야 한다.

## 6. 핵심 시스템 1 — YouTube Content Intelligence

목표는 현재 YouTube에서 실제로 제작되고 있는 영상들을 분석하여
"좋은 YouTube 콘텐츠가 어떤 방식으로 만들어지는지" 제작 패턴을 확보하는 것이다.

### 6.1 YouTube 데이터 수집

처음부터 YouTube 전체를 분석할 필요는 없다.
우리가 만들려는 콘텐츠와 관련성이 높은 분야부터 분석한다.

게임 스트리머 / 인터넷 방송 / 생방송 편집 영상 / 게임 하이라이트 / 합방 /
리액션 / 토크 / 예능형 콘텐츠 / 스트리머 콘텐츠

### 6.2 수집 대상

영상, 제목, 썸네일, 설명, 업로드 날짜, 영상 길이, 조회수, 좋아요, 댓글,
채널, 카테고리, 가능한 범위의 시청자 반응 데이터

### 6.3 영상 자체 분석

AI는 YouTube 영상을 단순히 시청하고 요약하는 것이 아니라
영상이 어떻게 제작되었는지를 분석한다.

**[영상 구조]**
영상 시작 방식 / 정보 공개 순서 / 사건 진행 / 장면 연결 / 결말 / 종료 방식

**[편집]**
컷 / 평균 장면 길이 / 확대 / 크롭 / 화면 전환 / 자막 / 강조 / 효과 / 효과음 /
BGM / 이미지 / 밈 / 리플레이

**[스토리텔링]**
어떤 정보를 먼저 보여주는가 / 어떤 정보를 늦게 공개하는가 / 어떤 장면을 생략하는가 /
어떤 장면을 반복하는가 / 서로 다른 시간대의 장면을 어떻게 연결하는가

**[인물]**
누가 중심 인물인가 / 누구의 반응이 중요한가 / 인물 간 관계가 어떻게 표현되는가

## 7. YouTube 영상에서 "제작 논리" 추출

단순히 "이 영상은 자막이 많다", "이 영상은 컷이 빠르다" 수준의 정보를 얻는 것만으로는
부족하다. AI는 한 단계 더 나아가 **"왜 이렇게 편집했는가?"**를 분석해야 한다.

```
원본 사건 발생
→ 결과 장면을 먼저 보여줌
→ 시청자의 궁금증 유도
→ 과거 장면으로 이동
→ 사건의 원인 설명
→ 사건 진행
→ 결과
```

이러한 과정을 하나의 "제작 패턴"으로 추출한다.

## 8. YouTube Content Knowledge

YouTube 영상들을 지속적으로 분석하면 다음과 같은 제작 지식을 구축할 수 있다.

콘텐츠 구성 패턴 / 편집 패턴 / 스토리텔링 패턴 / 장면 선택 패턴 / 영상 템포 /
자막 사용 패턴 / 반응 강조 방식 / 콘텐츠별 특징 / 제목 패턴 / 썸네일 패턴 /
영상 길이와 구성의 관계 / 시청자 반응과 영상 구성의 관계

**중요한 점:** 이 지식을 "고정된 규칙"으로 만들지 않는다.
AI가 새로운 생방송을 제작할 때 참고하는 제작 지식으로 사용한다.

---

## 9. 원본 생방송과 완성 YouTube 영상의 관계 학습

가능하다면 가장 중요한 학습 데이터는 다음과 같다.

```
원본 생방송 + 그 생방송을 기반으로 제작된 YouTube 영상
```

이 데이터를 통해 AI가 다음을 분석한다.

- 원본에서 어떤 장면이 선택되었는가
- 어떤 장면이 제거되었는가
- 어떤 장면이 연결되었는가
- 원본 시간 순서가 어떻게 변경되었는가
- 어떤 장면이 반복되었는가
- 어떤 장면이 강조되었는가
- 어떤 자막이 추가되었는가
- 어떤 효과가 사용되었는가
- 어떤 스토리로 재구성되었는가

이것을 통해 `원본 생방송 → 편집자의 선택 → 편집자의 구성 → 완성 YouTube 영상`
이라는 관계를 학습한다.

---

## 10. YouTube 학습과 복제의 차이

특정 YouTube 영상 하나를 그대로 복제하는 것이 목적이 아니다.

학습해야 하는 것은: 영상 구조의 특징 / 장면 선택 원리 / 편집 원리 /
정보 전달 방식 / 스토리텔링 방식 / 콘텐츠 유형별 특징 / 시청자 반응과 구성의 관계

```
Reference A / B / C / D
        ↓
공통적인 제작 패턴 분석
        ↓
YouTube 제작 지식
        ↓
새로운 생방송에 적용
        ↓
새로운 영상 제작
```

즉 "특정 영상을 복사한다"가 아니라
**"여러 실제 영상에서 제작 원리를 학습한다"**가 목표다.

## 12. Multimodal Analysis

생방송에서 다양한 정보를 추출한다.

**[음성]** 음성 인식 / 화자 구분 / 발화 내용 / 대화 / 말투 / 감정 / 중요한 발언

**[영상]** 인물 / 게임 화면 / 게임 상태 / 화면 변화 / 행동 / 시각적 사건

**[오디오]** 웃음 / 비명 / 환호 / 박수 / 침묵 / 효과음 / 음악 변화

모든 정보에는 타임스탬프를 연결한다. (예: 사건 A — timestamp: 03:21:42)

## 13. Long-Term Memory

수 시간짜리 방송을 단순히 자막 데이터로 저장하지 않는다.
방송에서 발생한 사건과 의미적 관계를 저장한다.

```
사건 A
  처음 언급  00:32:11
  관련 대화  01:14:22
  재언급     03:41:11
  갈등       04:21:09
  결과       05:12:44
```

AI는 이렇게 시간적으로 멀리 떨어진 장면도 같은 사건으로 연결할 수 있어야 한다.

## 15. 핵심 시스템 3 — Autonomous Content Discovery

방송 전체를 이해한 후 AI에게 다음 질문을 한다.

> "이 방송에서 독립적인 콘텐츠로 만들 가치가 있는 것은 무엇인가?"

결과: Candidate A / B / C / D ...
**후보의 개수는 정해져 있지 않다.**

---

## 16. 콘텐츠 후보

각 콘텐츠 후보는 단순한 클립이 아니다. 각 후보는 다음과 같은 정보를 가진다.

핵심 내용 / 관련 인물 / 관련 사건 / 관련 장면 / 시작 지점 / 주요 변화 / 결과 /
필요한 맥락 / 다른 사건과의 관계 / 독립적인 콘텐츠로서의 가능성

---

## 17. 콘텐츠 개수 결정

AI가 방송 전체를 분석한 결과에 따라 콘텐츠 개수를 결정한다.

```
방송 A → 장편 4개 + Shorts 7개
방송 B → 장편 2개 + Shorts 3개
방송 C → 장편 1개
방송 D → 제작 가치가 있는 콘텐츠 없음
```

이것을 모두 허용한다.

---

## 18. 콘텐츠 가치 판단

모든 후보를 영상으로 만들지 않는다.
AI가 각각의 후보를 분석하여 독립적인 콘텐츠로 만들 가치가 있는지를 판단한다.

```
후보 A → 독립적으로 이해 가능 / 사건이 완결됨 / 강한 반응 → 장편 영상 적합
후보 B → 재미는 있지만 결말이 없음 → 다른 장면과 결합 필요
후보 C → 짧지만 강한 장면 → Shorts 적합
후보 D → 맥락이 너무 많이 필요 → 제작하지 않음
```

## 19. 핵심 시스템 4 — Dynamic Content Planning

콘텐츠가 선정되면 AI가 다음을 결정한다.

> "이 콘텐츠를 어떤 방식으로 보여주는 것이 가장 좋은가?"

영상 구조는 하드코딩하지 않는다.

```
콘텐츠 A: 결과 장면 → 과거 장면 → 사건 원인 → 사건 진행 → 결과
콘텐츠 B: 평범한 대화 → 이상한 발언 → 주변 반응 → 사실 공개 → 후속 대화
콘텐츠 C: 게임 시작 → 실패 → 재도전 → 위기 → 성공
콘텐츠 D: 짧은 사건 → 반응 → 종료
```

콘텐츠마다 서로 다른 구조를 사용할 수 있다.

---

## 20. YouTube Content Knowledge와 결합

콘텐츠 기획 단계에서 앞에서 구축한 YouTube Content Knowledge를 참고한다.

입력: 현재 생방송에서 발견한 콘텐츠 + YouTube 제작 지식 → AI 제작 전략

예: "현재 콘텐츠와 유사한 YouTube 콘텐츠에서는 결과를 먼저 보여주는 방식이 자주 사용된다."

그러나 이것을 무조건 적용하지 않는다.
현재 콘텐츠의 실제 특성과 비교한 후 AI가 최종적으로 결정한다.

---

## 21. Scene Retrieval

AI가 만든 기획을 기반으로 원본 생방송 전체에서 필요한 장면을 검색한다.

질의 예:
- "사건이 처음 언급된 장면"
- "상대방이 처음 반응한 장면"
- "상황이 바뀐 장면"
- "결과가 발생한 장면"

`검색 결과 → 후보 장면 1~4 → AI 검증 → 최종 장면 선택`

---

## 22. Edit Planning

AI는 실제 영상 파일을 직접 편집하는 대신 편집 계획을 생성한다.

```
Scene A  원본 04:31:20 ~ 04:31:42  역할: 사건의 핵심 장면
Scene B  원본 01:12:11 ~ 01:13:04  역할: 사건의 배경
Scene C  원본 05:12:31 ~ 05:13:10  역할: 결과
```

각 장면에 필요한 편집 의도를 함께 지정한다.
자막 / 확대 / 크롭 / BGM / 효과음 / 그래픽 / 전환 / 오디오 조정

---

## 23. 자동 영상 제작

Renderer가 AI의 편집 계획을 실제 영상으로 만든다.

지원 기능: 컷 / 트리밍 / 장면 순서 변경 / 크롭 / 확대 / 자막 / 그래픽 /
효과음 / BGM / 오디오 정리 / 전환 / 렌더링

---

## 24. YouTube Packaging

완성된 영상에 대해 AI가 다음을 생성한다.
제목 / 설명 / 태그·메타데이터 / 썸네일 / 챕터 / 업로드 정보

제목과 썸네일 역시 고정된 템플릿을 사용하지 않는다.
YouTube에서 분석한 실제 콘텐츠 패턴을 참고하되 현재 영상의 내용에 맞춰 새롭게 생성한다.

## 25. YouTube 업로드


시스템이 안정화된 이후 자동 공개 기능을 선택적으로 사용할 수 있다.

재시청 구간 / 좋아요 / 댓글 / 공유 등

## 28. 전체 AI 학습 구조

**C. Performance Learning**
완성 YouTube 영상 → 실제 시청자 반응 → 성과 분석 → 제작 전략 개선

## 31. MVP 개발 단계

**MVP 1 — YouTube Content Intelligence**
목표: YouTube 영상이 어떻게 만들어지는지 AI가 분석할 수 있는지 검증
입력: YouTube 영상 데이터셋
출력: 영상 구조 / 편집 패턴 / 스토리 패턴 / 장면 선택 패턴 / 제목·썸네일 관계

**MVP 2 — Broadcast Understanding**
입력: 4~6시간 생방송
출력: 전체 방송 의미 구조 / 사건 / 인물 / 대화 / 관계 / 시간적 연결

**MVP 3 — Content Discovery**
출력: 방송에서 발견한 콘텐츠 후보. 사람이 AI 결과를 평가한다.

**MVP 4 — Source-to-Output Mapping**
원본 생방송 + 완성 YouTube 영상 → 어떤 원본 장면이 선택되었는지 분석

**MVP 5 — Dynamic Planning**
AI가 콘텐츠마다 영상 구조를 스스로 결정한다.

**MVP 6 — Automatic Editing**
AI의 편집 계획을 실제 영상으로 렌더링한다.

**MVP 7 — YouTube Packaging**
제목 / 썸네일 / 설명 / 챕터 / 업로드

**MVP 8 — Automatic Upload**
YouTube API를 통한 자동 업로드

**MVP 9 — Performance Learning**
YouTube 성과 데이터를 분석하여 제작 전략을 개선한다.

## 32. 첫 번째 MVP의 성공 기준

처음부터 자동으로 영상을 완성하는 것을 목표로 하지 않는다.
가장 먼저 다음을 검증한다.

```
6시간 생방송 입력
  ↓ AI 전체 분석
  ↓ 콘텐츠 후보 생성
  ↓ 사람이 실제 방송을 직접 확인
  ↓ AI가 발견한 콘텐츠가 사람이 발견할 만한 콘텐츠와 얼마나 일치하는지 평가
```

그리고 각 콘텐츠에 대해 다음을 평가한다.

- 관련 장면을 제대로 찾는가
- 서로 다른 시간대의 장면을 연결하는가
- 사건의 시작과 결과를 이해하는가
- 불필요한 장면을 제외하는가

## 33. 최종 제품 사용 방식

사용자는 생방송 파일 하나만 입력한다. (예: `6시간_생방송.mp4`)

예상 결과:

```
방송 분석 완료
의미 있는 콘텐츠 후보 8개 발견
  장편 후보 4개
  Shorts 후보 4개
```

AI가 각각을 판단한다.

```
콘텐츠 A → 12분 장편 영상
콘텐츠 B → 8분 장편 영상
콘텐츠 C → 15분 장편 영상
콘텐츠 D → Shorts
콘텐츠 E → 다른 콘텐츠와 결합
콘텐츠 F → 제작하지 않음
```

이후 AI가 각각의 영상에 맞춰 장면을 선택하고 구성하고 편집한다.

## 34. 최종 비전

이 프로젝트는 단순한 자동 편집기가 아니다.
단순한 하이라이트 추출기도 아니다.
단순한 영상 요약 AI도 아니다.

최종적으로 만들고자 하는 것은:

- "YouTube를 관찰하고 배우는 AI"
- "긴 생방송을 이해하는 AI"
- "콘텐츠를 발견하는 AI"
- "콘텐츠별 제작 전략을 결정하는 AI"
- "영상을 실제로 제작하는 자동화 시스템"
- "실제 시청자 반응을 다시 학습하는 시스템"

이 모든 것을 하나로 결합한 **AI 콘텐츠 프로듀서**다.

## 35. 최종 정의

> "YouTube에서 실제로 제작되는 콘텐츠를 지속적으로 분석하여 콘텐츠 제작 패턴과
> 편집 지식을 확보하고,
>
> 긴 생방송 하나를 처음부터 끝까지 분석하여 그 안에서 발생한 사건과 이야기,
> 인물, 관계 및 시간적 연결을 이해한 뒤,
>
> 방송에서 독립적인 콘텐츠로 만들 가치가 있는 내용을 스스로 발견하고,
>
> 콘텐츠의 개수와 종류를 스스로 결정하며,
>
> 각 콘텐츠의 특성에 따라 영상 구조와 장면 선택, 편집 방식을 스스로 결정하고,
>
> 실제 YouTube 영상으로 제작한 후,
>
> 업로드된 영상의 시청자 반응과 성과를 다시 분석하여 다음 콘텐츠 제작 능력을
> 지속적으로 개선하는
>
> 자율형 AI YouTube 콘텐츠 제작 시스템을 구축한다."

## 36. 핵심 철학

사람이 AI에게 "이런 구조로 만들어라"라고 계속 규칙을 입력하는 시스템이 아니다.

실제 YouTube 콘텐츠를 분석하여 "좋은 콘텐츠가 실제로 어떻게 만들어지고 있는가?"를
학습하고, 새로운 생방송을 분석하여 "이 방송에서는 무엇을 만들어야 하는가?"를
AI가 판단하며, 마지막으로 "이 콘텐츠는 어떻게 만들어야 하는가?"까지 AI가 스스로
결정하는 시스템을 만든다.

즉, 고정된 템플릿을 사용하는 AI가 아니라
**상황에 따라 판단하는 AI 콘텐츠 프로듀서**를 만드는 것이 본 프로젝트의 최종 목표다.
